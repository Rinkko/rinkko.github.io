> 这篇是凛子把洛天依《再生》CD 数字化时留下的操作记录。软件设置的一部分参考了 [B 站专栏《实体CD无损翻录/抓轨的通用教程（通过 Exact Audio Copy）》](https://www.bilibili.com/opus/925630344961458181)。凛子把自己实际遇到的问题也写了下来，方便之后抓其他碟时翻看。

把 CD 抓成文件听起来没什么难度：插入光盘，点击光驱图标，再用 Windows Media Player 的抓轨功能，最后静静等进度条走完。但如果打算留在自己的音乐库里长期保存，凛子还是希望文件除了能播放，还要能尽量确定它读得准确。

这次凛子用的是 Windows 和一台 **Lite-On DVD A DS8A5SH** 光驱，目标格式是 **FLAC**。过程并不算复杂，只不过凛子犯了一个非常离谱的扩展名错误，并且抓到的音轨也有些问题，好在最后靠 CUETools 把有问题的音轨修好了。

## 要求

- **Exact Audio Copy（EAC）**：从 CD 读取音频。
- **FLAC 编码器 `flac.exe`**：把读到的 PCM 音频无损压缩成 FLAC。
- **CUETools**：后续独立验证、必要时尝试 CTDB 修复。本文实际使用 **2.2.6**。
- 一个能正常读音乐 CD 的光驱，以及足够的磁盘空间。
-  一台能正常运行 Windows 的电脑（其实用 Linux 也行啦!）

下载位置： [EAC 官网](https://www.exactaudiocopy.org/) · [CUETools 发布页](https://github.com/gchudov/cuetools.net/releases) · [FLAC 官网](https://xiph.org/flac/)

## 配置 EAC

### EAC 选项

在 `EAC → EAC 选项` 里，主要需要检查的是这几项：

- **工具**：启用抓轨日志相关选项。UPC/ISRC、CD-Text 的读取能力要用确实含有这些信息的 CD 测试，读不出来也可能是光盘根本没写。（事实上大部分光盘都不会写呜呜呜）
- **标准化**：关闭。既然目的是保留原始 CD 音频，就别让抓轨流程主动改响度。
- **文件名**：直接使用 `%tracknr2%. %title%` ，得到 `01. 再声 Recall.flac` 这样的名字。需要分目录的话可以用年份、专辑艺人、专辑名等字段组合。
- **目录**：选择好输出文件夹。之后会保存 EAC 设置配置文件，避免换碟时重新调整。

专栏里对文件名替换、附加文件名、元数据源选择都有更细的讲解。凛子的想法是：文件名尽量还原专辑内的样子，最后再用 Music Tag v2 去整理音乐库的 FLAC 内部标签。尤其中文 V 曲，艺术家、作曲、虚拟歌手经常需要自己核对。

### 驱动器设置

按 `F10` 进入驱动器选项。

| 项目                             | 处理原则                                 |
| ------------------------------ | ------------------------------------ |
| 抓轨模式                           | 通常选择安全模式（Secure）                     |
| Accurate Stream（精确流）           | 按光驱的可靠检测结果设置                         |
| 音频缓存                           | 按实际检测和设备行为设置；拿不准时宁可按有缓存处理，避免错误复用缓存数据 |
| C2 错误报告                        | 不清除支不支持就不勾选                          |
| 读取偏移（Read Offset Correction）   | 优先使用 AccurateRip 识别的光驱偏移值            |
| Overread into Lead-In/Lead-Out | 只有确定支持的时候再启用                        |

这里有个容易被汉化误导的地方：凛子最初在“检测读取特性”窗口看到类似“不要装入盘片”的提示，空仓等了很久，只看到“未找到音轨”。实际这类检测要让 EAC 能读取音乐 CD 的音频扇区，应该先放入正常的音乐 CD。此处英文版本的正确翻译为：“不要增加系统负载”。

### 压缩选项

按 `F11`，进入 压缩选项 → 外部压缩程序。

| 项目        | 设置                           |
| --------- | ---------------------------- |
| 使用外部压缩程序  | 勾选                           |
| 参数传递方案    | 用户自定义编码器                     |
| 使用文件扩展名   | `.flac`                      |
| 压缩程序及路径   | 指向 `flac.exe`                |
| 添加 ID3 标签 | 不勾选（FLAC 使用 Vorbis Comments） |
| 检查外部程序返回值 | 勾选                           |

凛子用过的简化 FLAC 命令是：

```text
-8 -V -T "ARTIST=%artist%" -T "TITLE=%title%" -T "ALBUM=%albumtitle%" -T "DATE=%year%" -T "TRACKNUMBER=%tracknr%" -T "GENRE=%genre%" %source% -o %dest%
```

`-8` 是 FLAC 的最高压缩等级，`-V` 是编码验证。所有有效的 FLAC 压缩等级都是无损的，但更高的压缩等级可以让压缩后的文件更小，为了节省宝贵的硬盘空间，凛子毅然决然的选择了最高压缩。填完后记得点测试编码器。（不然导错了都没处哭!抓一张盘的实际还挺长的!）

B 站原教程还有一条更完整的参数串，包含 `ALBUMARTIST`、`COMPOSER`、碟号、歌词文件、以及 `--picture="%coverfile%"` 的封面写入；如果想完整保留这些信息，可以直接参照[原文“压缩选项 → 外部压缩程序”一节](https://www.bilibili.com/opus/925630344961458181)设置并测试。

凛子在此处明明选了 `flac.exe`，也填了 FLAC 的参数，但“使用文件扩展名”忘记从 `.mp3` 改成 `.flac`。最终出现一堆 `.mp3` 文件，看起来像是抓成有损格式。后来用 MediaInfo 检查，发现内部编码仍是 FLAC，只是文件名错了。把扩展名改回 `.flac` 就行，完全不用再压缩一次。

Warning: 真正的 MP3 转成 FLAC 当然不能恢复已经丢失的音频信息!

## 曲目信息、封面和间隙

把 CD 放进去后，EAC 可能能从数据库带出曲目名称，也可能什么都找不到。对冷门专辑、同人盘、中文 V 曲来说，这很常见。

凛子这张专辑在数据库里查询不到任何元数据，只能手动填写标题，专辑名和作曲等内容。封面则是在 Twitter (现在叫 X 啦!) 找到了画师的原图，并手动裁剪为 1000px 大小。EAC 支持把本地 JPG/PNG 拖到主界面右侧 CD 封面区域来添加图片。（虽然 EAC 支持任意大小的图片，但最好是正方形，并且尺寸为 1000px）

这里说一下，如果使用 Music Tag 等软件对文件进行元数据后处理的话，这里只要填个歌词和专辑名就好啦！

### 间隙检测

原教程推荐抓轨前用 `操作 → 检测间隙`，并将间隙追加到上一轨，再按需生成 CUE，但实际上，目前的 EAC 版本已经会自动追加间隙了，所以直接检测即可。

凛子用默认方法时，检测到**第 8 轨**就会卡住，换了一种间隙检测方法才通过。这个问题和后面音频抓取时第 8 轨重读都发生在同一轨，或许是买到的盘就有问题吧...？（但也没有打算退换货啦）。

如果想以后重建 CD 的曲目位置，建议保存 CUE。尤其在乎 INDEX、音轨间隙或特殊连续曲目时更有用。

## 正式抓轨

终于可以开始抓轨了！检查好标签和设置后，在 EAC 里选择复制所选音轨的已压缩模式就开始抓啦！

要注意，这里的“已压缩”是指调用已配置的编码器（也就是之前配置的 FLAC），可不是说音频文件会被压缩成无损喔。

起初进度很正常，直到第 8 轨的时候 EAC 的纠错方格变为全红，状态里不停出现读取重试和同步错误，速度也只有大约 0.9×，但进度已经一大半了，自然不可能在这里停下。

总之，姑且在光驱的一阵暴响中抓完了 8 轨。

### 并不好看的 EAC 日志

这张专辑一共有 12 轨，EAC 的 AccurateRip 结果是：

- **通过**：1、3、6、7、9、10
- **未通过**：2、4、5、8、11、12

其中第 8 轨还有：

```text
可疑位置 0:02:19
不能准确地校验
```

随 EAC 运行的 CUETools DB 插件也查到了数据库：

```text
Submit result: insufficient quality
Track 8: Differs in 14 samples @02:19:33
```

其他出错音轨的差异分别是：第 2 轨 9 samples、第 4 轨 9、第 5 轨 4、第 11 轨 14、第 12 轨 45。虽然这几个数字很小，但既然要抓轨，就要追求完美嘛——有验证数据库的话，干脆就试试修复好了!

在此之前，先推荐一下这个网站—— [cambia](https://logs.musichoarders.xyz/)，将输出文件夹里的 log 文件上传，可以看到这次抓取的评分，虽然没有什么用，但是可以自己满足自己嘛!~~因为坏轨，凛子这次的抓取只有B级的评分呜呜呜~~

## CUETools 修复

### Verify

把同一张专辑的 **12 首 FLAC 放在一起**，在 CUETools 左侧目录浏览中选择识别出来的整张专辑分组。凛子的界面显示的是：

```text
再生 (disc 1): 12 files
```

这时候选中就可以添加整个专辑了。

选择 ``Action: Verify``

启用 CTDB / AccurateRip 验证后点击 `Go`，得到的结果与 EAC 的日志一致：6 首准确、6 首不匹配。

### Repair

先备份原来的 12 首文件,将设置改为：

| 项目           | 值                       |
| ------------ | ----------------------- |
| Action       | `Encode`                |
| 脚本           | `repair`（不要选`default`!） |
| Mode         | `Tracks`                |
| Audio Output | `Lossless`              |
| 格式           | `flac`                  |
| 编码器          | `cuetools`              |
| 压缩滑条         | 拉到最大（文件体积最小）            |
| Output       | 修复后的保存目录                |

选择专辑时会弹出元数据窗口，确认专辑信息无误后继续。

这次执行后出现了最想看到的一行：

```text
CUETools DB: corrected 95 errors.
```

随后 12 首的 AccurateRip 状态**全部**变成了 `Accurately ripped`。此前第 8 轨错误的 AR v2 CRC 为 `84B2D2DC`，修复后变成数据库匹配的 `BA0B2007`。

### Verify Again

修复窗口提示成功还不够，为了保险，凛子又用 `Verify` 验证了**新输出目录**。最终日志里终于出现了想要的结果：

```text
CTDB: 12 / 12 Accurately ripped
AccurateRip: 12 / 12 Accurately ripped
```

包括之前问题最多的第 8 轨：

```text
Track 8 CTDB: (60/63) Accurately ripped
Track 8 AccurateRip: (0+7/7) Accurately ripped
```

准确说，这证明当前输出的音频与 AccurateRip 和 CTDB 中的多份参考抓轨一致，可以作为高可信度的无损归档！可喜可贺可喜可贺！

## 后记

凛子以前一直都是用 Windows Media Player 自带的翻录功能简单抓抓 CD，直到这次折腾下来，才发现想要制作一份尽可能完整、准确的专辑数字副本，原来还有这么多地方要注意。

比起依赖流媒体会员听歌，凛子总觉得那样的音乐多少有些飘忽不定。今天还能听到的歌，或许哪天就因为版权变动而悄悄下架了。说到底，那些音乐似乎从来没有真正属于过自己。~~这里要大力批评一下任天堂的钥匙卡

所以凛子还是更喜欢让音乐以确切的数据形式存在——尤其是未经有损压缩、尽可能忠实于原始 CD 的高质量音频文件。把它们一首首整理好，连同封面、歌词和专辑信息一起，安安静静地存放在自己的 NAS 里。

即使哪天世界大战爆发了，平台没了，网络断了，这些音乐也依然在那里，随时都在那里。

怎么说呢，会有一种奇妙的安心感。
